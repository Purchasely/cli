Recipes

Copy a file, set two secrets, and the Purchasely CLI works for you every day in GitHub Actions. Each recipe only reads your account: it changes nothing in Purchasely.

  1. Daily key metrics in Slack
  2. Weekly key metrics in Google Sheets
  3. Check the placements before a release
  4. A history of your configuration in git

Before you start

  1. Create a Management API key in the Console. Use a key with read access only if you can: these recipes never write.
  2. In your GitHub repository, open Settings, then Secrets and variables, then Actions. Add the key as the repository secret PURCHASELY_API_KEY. The CLI reads it from the environment and never prints it.
  3. Replace app_xxx with the id of your app. purchasely apps list shows it.

Each workflow installs the CLI in two lines. The CLI does not update itself in CI. jq is already on the GitHub runners. The times of cron are in UTC.

Daily key metrics in Slack

Every weekday morning, a Slack channel gets the MRR, the active subscriptions, the paywall viewers and the conversions of the last 7 days.

You need

  • The secret SLACK_WEBHOOK_URL: an incoming webhook of your Slack workspace (Slack app settings, Incoming Webhooks).
# .github/workflows/purchasely-slack.yml
name: Purchasely KPIs to Slack
on:
  schedule:
    - cron: "0 8 * * 1-5"   # 08:00 UTC, Monday to Friday
  workflow_dispatch:
jobs:
  report:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - name: Install the Purchasely CLI
        run: |
          curl -fsSL https://cli.purchasely.io/install.sh | sh
          echo "$HOME/.local/bin" >> "$GITHUB_PATH"
      - name: Send the key metrics to Slack
        env:
          PURCHASELY_API_KEY: ${{ secrets.PURCHASELY_API_KEY }}
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK_URL }}
          APP_ID: app_xxx
        run: |
          purchasely dashboard summary --app "$APP_ID" --days 7 \
            | jq '{text: ("*Purchasely, last 7 days*\n"
                + ([.panels[] | "\(.name): \(.value)"] | join("\n")))}' \
            | curl -fsS -H 'Content-Type: application/json' \
                --data @- "$SLACK_WEBHOOK_URL"

The message looks like this:

*Purchasely, last 7 days*
MRR: 1250
Active subscriptions: 310
Paywall unique viewers: 4210
Conversions: 87
  • MRR is today's value, in the dashboard currency of the app. Viewers and conversions are the total of the 7 days.
  • Change --days for another range, from 2 to 730 days.

Weekly key metrics in Google Sheets

Every Monday, the sheet gets one row: the first day, the last day, MRR, active subscriptions, paywall unique viewers and conversions.

You need

  • A Google Sheet with this header row: From, To, MRR, Active subscriptions, Paywall unique viewers, Conversions.
  • In the sheet, open Extensions, then Apps Script, and paste the script below. Then click Deploy, New deployment, type Web app. Set Execute as to Me and Who has access to Anyone. Copy the web app URL.
  • The secret SHEET_WEBHOOK_URL: the web app URL. Anyone with this URL can add rows, so keep it secret.
function doPost(e) {
  const row = JSON.parse(e.postData.contents);
  SpreadsheetApp.getActiveSpreadsheet().getSheets()[0].appendRow(row);
  return ContentService.createTextOutput("ok");
}
# .github/workflows/purchasely-sheets.yml
name: Purchasely KPIs to Google Sheets
on:
  schedule:
    - cron: "0 7 * * 1"   # 07:00 UTC, every Monday
  workflow_dispatch:
jobs:
  report:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - name: Install the Purchasely CLI
        run: |
          curl -fsSL https://cli.purchasely.io/install.sh | sh
          echo "$HOME/.local/bin" >> "$GITHUB_PATH"
      - name: Add one row to the sheet
        env:
          PURCHASELY_API_KEY: ${{ secrets.PURCHASELY_API_KEY }}
          SHEET_WEBHOOK_URL: ${{ secrets.SHEET_WEBHOOK_URL }}
          APP_ID: app_xxx
        run: |
          purchasely dashboard summary --app "$APP_ID" --days 7 \
            | jq -c '[.from, .to] + [.panels[].value]' \
            | curl -fsSL -H 'Content-Type: application/json' \
                --data @- "$SHEET_WEBHOOK_URL"
  • Do not add -X POST to curl. Google answers with a redirect, and -L must follow it with a GET.

Check the placements before a release

The build fails when a placement that the new app version needs does not exist in Purchasely. You find the error before your users do.

You need

  • The list of the placement ids that your code uses, in REQUIRED, separated by spaces.
# .github/workflows/purchasely-check.yml
name: Purchasely release check
on:
  pull_request:
  workflow_dispatch:
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - name: Install the Purchasely CLI
        run: |
          curl -fsSL https://cli.purchasely.io/install.sh | sh
          echo "$HOME/.local/bin" >> "$GITHUB_PATH"
      - name: Check the placements that this app version uses
        env:
          PURCHASELY_API_KEY: ${{ secrets.PURCHASELY_API_KEY }}
          APP_ID: app_xxx
          REQUIRED: "onboarding settings_paywall"
        run: |
          purchasely placements list --app "$APP_ID" \
            --fields vendor_id --per-page 100 --out placements.json
          for id in $REQUIRED; do
            jq -e --arg id "$id" 'any(.placements[]; .vendor_id == $id)' \
              placements.json > /dev/null \
              || { echo "::error::Placement $id is missing in Purchasely"; exit 1; }
          done
  • --per-page 100 reads up to 100 placements in one request. The default page has 25.
  • Put the same step in your release workflow, before the store upload.

A history of your configuration in git

Every night, the workflow saves your placements, audiences, campaigns, A/B tests, flows and products as JSON files, and commits the changes. Each change in the Console becomes a diff that you can read and review.

You need

  • A git repository for the backup. The workflow commits to it, so it needs contents: write.
# .github/workflows/purchasely-backup.yml
name: Purchasely configuration backup
on:
  schedule:
    - cron: "0 2 * * *"   # 02:00 UTC, every day
  workflow_dispatch:
permissions:
  contents: write
jobs:
  backup:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - name: Install the Purchasely CLI
        run: |
          curl -fsSL https://cli.purchasely.io/install.sh | sh
          echo "$HOME/.local/bin" >> "$GITHUB_PATH"
      - name: Export the configuration
        env:
          PURCHASELY_API_KEY: ${{ secrets.PURCHASELY_API_KEY }}
          APP_ID: app_xxx
        run: |
          mkdir -p purchasely
          for r in placements audiences campaigns ab-tests flows products; do
            purchasely "$r" list --app "$APP_ID" --fields '*' --per-page 100 \
              --out "purchasely/$r.json"
          done
      - name: Commit the changes
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          git add purchasely
          git diff --cached --quiet && exit 0
          git commit -m "Purchasely configuration of $(date -u +%F)"
          git push
  • --out writes each answer to its file. Do not use >: above 200 KB the CLI writes the answer to a file and prints only its path.
  • --fields '*' asks for every field. Two runs with no change give the same files, so a commit means a real change.
  • To read a change: git log -p purchasely/placements.json.
