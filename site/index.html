Purchasely in your terminal

Read your data, change your configuration with guardrails, and automate the rest. One tool for you, your CI pipeline and your AI coding agent.

curl -fsSL https://cli.purchasely.io/install.sh | sh

macOS and Linux. Needs Node 20 or later. Then purchasely auth login with a Management API key.

# You: the key metrics of an app, with charts
$ purchasely dashboard summary \
    --app app_xxx --output table

# Your CI: fail when a placement is missing
$ purchasely placements list --app app_xxx \
    --fields vendor_id --per-page 100 | jq -e \
    'any(.placements[]; .vendor_id == "onboarding")'

# Your AI agent: find a command in plain words
$ purchasely search "start an a/b test"
[{ "command": "purchasely ab-tests start …", … }]

One tool, every team

The Console is the place to design and explore. The CLI is the place to repeat, script and automate. It covers every resource of the Management API, and gets a new command each time the API gets a new endpoint.

Mobile developers

Integrate with your real ids

Your AI agent reads your placements, products, plans and custom events from your account, then writes the SDK code with the real values. No copy and paste from the Console.

Growth and product teams

Change configuration with a safety net

Rename placements, start or stop A/B tests, update audiences. Every write shows its request first with --dry-run, and a risky change asks for confirmation.

Data and BI

Your numbers, in your tools

MRR, active subscriptions, paywall viewers and conversions as JSON. Send them to a spreadsheet, a database or your own dashboard with a short script.

Platform and CI

Checks before each release

A CI job reads your configuration and fails when something is missing. Stable exit codes and JSON output make the result easy to test.

AI coding agents

A tool your agent already knows

Claude Code, Codex, Cursor and the others run shell commands well. The CLI gives them search, help, JSON and guardrails, with no extra server to set up.

What you can do with it

Replace app_xxx with an id from purchasely apps list. These examples need jq for the pipes.

A dashboard that updates itself

The Purchasely plugin in your AI assistant answers questions about your data. The CLI lets a script get the same data every day, with nobody in the loop. Use them together.

1. Ask your AI assistant once. In Claude Desktop, or any AI assistant that works on your computer:

"Build a dashboard of our paywall conversions. Install the Purchasely CLI, and write a script that updates the data every morning."

2. The script does the rest. The assistant asks your permission, installs the CLI and writes a script that calls it, for example:

purchasely dashboard summary --app app_xxx \
  --days 30 --out data/metrics.json

The update does not use the AI: it is fast, it gives the same result each time and it costs no AI credits. The script runs when your computer is on. To run it every day on a server, use the recipes.

Build your own dashboard

The same numbers as the Console dashboard, ready for a cron job, a Slack message from your own script, or a sheet.

purchasely dashboard summary --app app_xxx --days 90 \
  --out metrics.json

Add --output table to read them yourself, with a sparkline per metric. purchasely dashboard lists every dashboard.

Guard your releases in CI

A GitHub Actions job that fails when the placement your new app version needs does not exist.

- run: |
    curl -fsSL https://cli.purchasely.io/install.sh | sh
    echo "$HOME/.local/bin" >> "$GITHUB_PATH"
- run: |
    purchasely placements list --app "$APP_ID" --fields vendor_id \
      --per-page 100 | jq -e 'any(.placements[]; .vendor_id == "onboarding")'
  env:
    PURCHASELY_API_KEY: ${{ secrets.PURCHASELY_API_KEY }}

Add your Management API key as the repository secret PURCHASELY_API_KEY: Settings, Secrets and variables, Actions. The CLI reads it from the environment and never prints it.

Keep a history of your configuration

Save your placements, audiences, campaigns and A/B tests as JSON in a git repository. Each change is a diff you can review.

for r in placements audiences campaigns ab-tests; do
  purchasely "$r" list --app app_xxx --per-page 100 --out "config/$r.json"
done
git diff config/

Change a placement, see the request first

The dry run prints the request and sends nothing. A write always names its environment.

purchasely placements update --app app_xxx --id plc_xxx \
  --data '{"name":"Onboarding"}' --env prod --dry-run

Remove --dry-run to send it. A risky change, such as the delete of a placement in use, stops and shows its impact first.

CLI or MCP server?

An MCP server gives tools to an AI chat app. A CLI gives commands to anything that has a shell: you, a script, a CI job, or a coding agent. The two do not compete. Use the one that fits where the work happens.

The CLI and an MCP server, compared
CLIMCP server
Who runs itYou, your scripts, your CI and your coding agent, with the same commandsAn AI app that supports MCP
Cost for an agentLow: the agent reads the help of one command when it needs it, and filters the output with jqHigher: the tool list goes into the context, and each result comes back in full
Combine with other toolsPipes, files, jq, git, cronOnly through the AI app
Repeat the same taskA script runs it again, with no AI and no tokensThe model runs it again, each time
CI and automationYes: an environment variable for the key, stable exit codesNot made for it
Needs a shellYesNo: it also works in chat and browser apps
Access per userOne API key per person or per pipelineCan use a login per user (OAuth), which suits shared or hosted agents

Use the CLI when

  • you work in a terminal or an IDE with a coding agent;
  • the task must run again: a script, a cron job, a CI step;
  • the output goes into another tool or a file.

Use an MCP server when

  • the AI app has no shell, such as a chat app;
  • an agent acts for many users, each with their own login.

Made for AI coding agents

The CLI behaves the same for a person and for an agent. Give the agent these rules, or install the Purchasely AI plugin, which has them.

  1. Find the command with purchasely search "<task>". The first result is the best match. purchasely reference --format json gives the whole tree.
  2. Read the help of that one command: purchasely <resource> <action> --help.
  3. Read the JSON on stdout and the exit code. Use --fields to ask for less data.
  4. Run --dry-run before every write and show the request to the user.
  5. Never pass --yes without the approval of the user.

Give the agent the key through PURCHASELY_API_KEY or purchasely auth login. Never put the key in a command.

# User: rename the onboarding placement
$ purchasely search "update a placement"
[
  {
    "command": "purchasely placements update --app app_xxx --id <id> --data @body.json --env prod",
    "method": "PATCH",
    …
  }
]
$ purchasely placements update --help
$ purchasely placements update --app app_xxx --id plc_xxx \
    --data '{"name":"Onboarding"}' --env prod --dry-run
{
  "method": "PATCH",
  "url": "https://api.purchasely.io/management/v1/applications/app_xxx/placements/plc_xxx",
  "headers": {
    "Authorization": "Bearer <redacted>",
    "Accept": "application/json",
    "User-Agent": "purchasely-cli/<version> (-; -)",
    "Content-Type": "application/json"
  },
  "body": {
    "name": "Onboarding"
  }
}
# Agent: this is the request. Send it?
# User: yes
$ purchasely placements update --app app_xxx --id plc_xxx \
    --data '{"name":"Onboarding"}' --env prod

The Purchasely AI plugin

The rules above make the CLI safe for any agent. The plugin adds Purchasely knowledge to the agent: SDK integration, review, debug and migration.

One command

purchasely ai install
  1. It finds Claude Code, Codex, Copilot CLI, Gemini CLI, Cursor and OpenCode on your machine. Use --agent to choose one.
  2. purchasely ai status shows the agents and the plugin version. purchasely ai update and purchasely ai uninstall change only what ai install registered.
  3. The CLI also updates the plugin once a day in the background, only in those agents.

6 skills

purchasely-cli, sdk-expert, integrate, review, debug and migrate.

Ask the agent to integrate the SDK with your real placements, products, plans and custom events, read by the CLI from your account. Ask it to debug, review or improve your integration.

The CLI does not return the SDK API key of an app. Copy it from the Console (App settings) into your app configuration. The agent does not ask for it.

Safe by default

The guardrails are in the CLI, not in the prompt. They work the same for a person, a script and an agent.

A dry run on every write
--dry-run prints the method, URL, headers and body, and sends nothing. The key shows as <redacted>. It works without a key.
Explicit environment
A write without --env is refused, also with --dry-run. Reads use prod by default.
Confirmation for risky changes
When the API asks for a confirmation, the CLI shows the impact. In a terminal, it asks you first. In a script, it stops with exit code 8 and gives a token that you send back with --confirm-token within 5 minutes.
Rate limits handled for you
A built-in limiter, shared by all CLI processes on your machine, stays under the API limits. On a 429, the CLI waits for the time the server gives and slows down. After too many rejections it stops with exit code 7.
Your key stays secret
The key is in the macOS keychain, or in a file only you can read. It is never printed: status shows its last 4 characters and the usage log keeps no key.
Output for scripts
JSON on stdout, one JSON error on stderr, and stable exit codes: 0 success, 3 no key, 4 forbidden, 6 not found, 7 rate limited, 8 confirmation required, 10 write refused. An answer over 200 KB goes to a file.
What the CLI sends

Management commands go to api.purchasely.io with your key. The User-Agent header carries the CLI version and your --reason value.

Once a day, the CLI asks cli.purchasely.io for the latest version. purchasely ai downloads the public Purchasely AI plugin from GitHub.

Every command, documented
The CLI reference has the help of every command. purchasely --help, man purchasely and shell completion (purchasely completion zsh) give the same in your terminal.

Start in one minute

One command installs the CLI under ~/.local/share/purchasely/install and links purchasely into ~/.local/bin or ~/bin. Node 20 or later must be installed first.

  1. Run the installer

    curl -fsSL https://cli.purchasely.io/install.sh | sh

    It downloads the latest version and checks its checksum. It uses ~/.local/bin or ~/bin if one of them is already on your PATH. Else it creates ~/.local/bin and adds one line to your shell profile: ~/.zshrc for zsh, ~/.bashrc and ~/.bash_profile for bash, ~/.profile for other shells. It never uses sudo.

    Open a new terminal if the command is not found.

  2. Log in with a Management API key

    purchasely auth login

    Create the key in the Purchasely Console, from the account menu, in Management API keys. It is not the SDK API key of your app. The CLI asks for the key with a hidden prompt. In CI, set PURCHASELY_API_KEY as a secret instead.

  3. Read your first data

    purchasely apps list --output table

    It prints your applications with their ids. Use an id as --app in the other commands.

Uninstall

Remove the install folder and the purchasely link in your bin folder. command -v purchasely shows the link.

rm -rf ~/.local/share/purchasely/install
rm "$(command -v purchasely)"

Updates

The CLI keeps itself up to date. You do not need to run the installer again.

Automatic

Once a day, the CLI checks for a new version in the background. It downloads and installs it in a separate process, so your command does not wait. The new version is used on the next run.

Now

purchasely update

Checks and installs the latest version at once.

Off

export PURCHASELY_DISABLE_AUTOUPDATE=1

The automatic check also stays off when the CI variable is set, so a pipeline always runs the version it installed.
